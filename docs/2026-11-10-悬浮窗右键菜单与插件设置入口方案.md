# PNM 悬浮窗右键菜单与「插件设置」入口方案

日期：2026-11-10｜状态：已施工（D1 按 A 执行），全链验收通过（见 §7）

## 1. 需求与目标

PNM 悬浮信息窗口（`CTooltipPopup`，hover TM 窗口时弹出的速率面板）目前没有任何
右键功能。本方案两步走：

1. 给悬浮窗加右键菜单（基础设施：消息分支 + 菜单弹出 + 菜单期守卫）；
2. 菜单首项「插件设置」，点击直接打开 PNM 设置窗（即 TM
   「选项设置→插件→ProcessNetMonitor→插件设置」弹出的同一个窗）。

**口径边界**：只动 PNM 自己的悬浮窗（popup）。TM 悬浮窗/任务栏窗上 PNM 显示项的
右键（`MT_RCLICKED`，`plugin_main.cpp:409-423`）保持现状——收 popup 后放行 TM
自己的菜单，不改。

## 3. 改动点

### 3.1 tooltip_popup.h：声明

```cpp
bool m_menu_open = false;              // 菜单期守卫（供 HoverTick 查询）
void ShowContextMenu(int x, int y);
bool IsMenuOpen() const { return m_menu_open; }
```

### 3.2 tooltip_popup.cpp：WM_CONTEXTMENU 分支 + ShowContextMenu 实现

HandleMessage 加分支（`lp==-1` 键盘触发时 GetCursorPos 兜底，PTM 同款）：

```cpp
case WM_CONTEXTMENU:
    ShowContextMenu(GET_X_LPARAM(lp), GET_Y_LPARAM(lp));
    return 0;
```

`ShowContextMenu` 抄详情窗模板，骨架：

```cpp
void CTooltipPopup::ShowContextMenu(int x, int y) {
    if (x == -1 && y == -1) { POINT pt; GetCursorPos(&pt); x = pt.x; y = pt.y; }
    m_menu_open = true;                          // RAII 或 try/finally 语义复位
    HMENU hMenu = CreatePopupMenu();
    AppendMenuW(hMenu, MF_STRING, 1, TR(L"插件设置"));
    int cmd = TrackPopupMenu(hMenu, TPM_RETURNCMD | TPM_RIGHTBUTTON, x, y, 0, m_hwnd, NULL);
    DestroyMenu(hMenu);
    if (cmd == 1)                                 // ★ 处理放守卫复位之前：
        CProcessNetPlugin::Instance().ShowOptionsDialog(m_hwnd);  // 模态期 popup 冻结
    m_menu_open = false;
}
```

两个刻意的顺序（与详情窗 1775 行先复位后处理不同，原因见下）：

- **命令处理放在 `m_menu_open` 复位之前**：模态消息循环期间守卫保持置位 →
  HoverTick 不收 popup → 悬浮窗冻结原状直到设置窗关闭（PTM 173786a 的
  m_menu_open 冻结语义平移，那边右键开设置免费搭车，这边要显式保序）。
- **parent = popup 自己**：设置窗以悬浮窗为锚 clamp 居中（既有逻辑）；模态期
  popup 被 EnableWindow(FALSE) 禁用，防「设置开着还能操作悬浮窗」。返回值
  （OptionResult）内部调用忽略——设置窗 WM_COMMAND OK 分支本就即时保存+应用。

### 3.3 plugin_main.cpp HoverTick：菜单期守卫

收 popup 判定之前加（`plugin_main.cpp:1305` 函数头附近）：

```cpp
if (m_popup.IsMenuOpen()) return;   // 菜单/设置模态期不收 owner
```

**为什么必须有**：PTM 实锤过的同构坑（173786a 注释原文：「纯 hover 态下鼠标移向
菜单（窗外）会触发宽限后 HideGroup 把菜单 owner 闪关」）——popup 是 hover 出现的
tooltip 性质窗，鼠标从 popup 移向菜单项（或设置窗）即「光标离开」，100ms 后
HoverTick 收起 popup；菜单 owner 被 DestroyWindow/隐藏会导致菜单失效或残影。
治本 = 菜单期状态机整体冻结，不是事后补丁。

## 4. 风险与对策

| # | 风险 | 对策 |
|---|---|---|
| R1 | `WS_EX_NOACTIVATE` 窗口上 TrackPopupMenu 的经典问题：菜单可能「点击外部区域不关闭」（菜单关闭依赖前台窗口） | 施工后提权探针/后台 UI 实测三态：①正常弹出 ②点击菜单项生效 ③点击菜单外能关闭。若③失灵：TrackPopupMenu 前 `SetForegroundWindow(m_hwnd)`（tooltip 类窗口经典处理）重测，实测结论留档，不留猜 |
| R2 | 模态循环嵌在 HandleMessage 栈内 | 与 TM 调用链同构（TM 也在消息处理栈里调 ShowOptionsDialog），PNM 既有生产模式，无新增风险 |
| R3 | 设置窗重入（TM 菜单路径开着一个，再从 popup 右键开） | PNM 设置窗保存的是即时生效型（WM_COMMAND OK 即保存），但双实例双模态循环仍应防：ShowOptionsDialog 入口 FindWindow 已开实例 → 拉前台 return（与 PTM 同步加，同款写法） |
| R4 | popup 恒 HTCLIENT + NOACTIVATE，WM_CONTEXTMENU 生成路径（RBUTTONUP → DefWindowProc 翻译） | 子类化窗口默认 DefWindowProc 处理链 intact，case 直接加即可；实测覆盖（R1 三态一并验） |
