# ProcessNetMonitor v1.17.0 — 修复详情窗口最小化后无法恢复（issue #18），详情窗口与 ETW 采集性能优化

## 修复

- **详情窗口最小化后无法恢复**（v1.16.7，[issue #18](https://github.com/deYangar/ProcessNetMonitor/issues/18)）：详情窗口此前不进任务栏，点标题栏的最小化按钮，窗口会退化成一条孤零零停在桌面上的小标题条（截图里的细条），找不到任何恢复入口。现在窗口在任务栏保留按钮——最小化后**点任务栏图标即可恢复原大小**（与火绒一致），Win+D 最小化后再按 Win+D 也能正常恢复；从 TM 菜单/悬浮窗重新打开时同样恢复正常尺寸

## 性能优化

- **详情窗口连接列表渲染提速**：展开连接数多的进程（如浏览器上百条连接）时，此前每秒刷新、每次滚动与点击都会为每条连接行现场创建 GDI 上下文测量归属地文本的换行高度、并重复查询归属地——列表越长 CPU 白烧越多，滚动和点击跟手度下降。现在行高与归属地结果按连接缓存，同一连接只测一次（窗口宽度或字体变化时自动失效重算），展开大列表的滚动与点击恢复流畅

- **ETW 采集热路径瘦身**：内部诊断用的本地地址采样此前无论调试日志开关与否，都会在每个网络事件上执行；在事件布局识别异常的场景下，5 秒窗口内可积累上万个地址节点持续消耗 CPU 与内存。现在仅在开启调试日志时采样，默认情况下事件处理路径零额外开销

## 安装前提

1. Windows 10/11（推荐 64 位）
2. TrafficMonitor 主程序（插件版）
3. 插件以管理员权限运行时可启用 ETW 内核采集（更准）；普通权限自动回退传统采集并提示

## 已知说明

- TUN 代理模式下，走代理的应用流量归属代理进程（如 mihomo），应用侧 TUN 重复流量不显示（与 AppNetworkCounter 一致）
- 代理进程与应用之间的虚拟转发流量（TUN 用户态）无法通过内核 ETW 观测，不显示
- 与 AppNetworkCounter 等 ETW 工具共用时：先启动的一方占用 NT Kernel Logger；后启动的 TM 进入附加模式（悬浮窗有黄色警告提示）
- ETW 占用者检测为尽力而为（Windows 无官方 API，普通权限下为已知工具名单识别）
- IP 归属地库（ip2region）首次使用时自动下载，失败会提示；可关闭或配置代理
