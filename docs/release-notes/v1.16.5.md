# ProcessNetMonitor v1.16.5 — 根治多线程竞态导致的堆损坏崩溃，治理不稳定网络反复重建与长期运行磁盘占用

## 修复

本版修复主体来自社区贡献 @Mahantor（[PR #17](https://github.com/deYangar/ProcessNetMonitor/pull/17)），后在其基础上补全了退避覆盖、锁内写路径与逐出摊销等遗漏（dc82493）。

- **TrafficMonitor 进程随机崩溃（0xc0000374 堆损坏 / 0xc0000005 访问违例），不稳定网络下一天可崩多次**：插件内部 ETW、传统捕获、刷新定时器、TM 宿主 UI 多条线程间的共享状态长期无锁访问（并发读写 `std::string`、悬浮提示行指针逃逸出临界区后继续使用、语言热重载无锁换表），堆元数据被直接写坏、崩溃点随机极难定位。现已全部改为持锁访问或锁内快照，悬浮提示改双缓冲原子发布，刷新定时器加可重入保护

- **VPN 等不稳定网络下字节捕获反复启停、socket 每 5 秒重建一次**：开关加 30 秒防抖，启用失败按 5 秒→300 秒指数退避；立即启用与连接线程每 5 秒的周期检查两条重建路径都判退避；退避按绑定目标匹配，用户切换网卡立即放行，不受退避限制

- **长期运行的内存与磁盘占用失控**：ETW 进程表无上限增长（上报机器实测累计 10 万+ 条）——现硬上限 4096 条，超限一次逐出到低水位 3500；诊断日志不轮转（实测 43MB）——现 8MB 轮转并保留 `.bak`；崩溃转储原为全量 dump（实测累计 1.4GB）——现改 MiniDump 且最多保留 3 份

## 安装前提

1. Windows 10/11（推荐 64 位）
2. TrafficMonitor 主程序（插件版）
3. 插件以管理员权限运行时可启用 ETW 内核采集（更准）；普通权限自动回退传统采集并提示

## 已知说明

- TUN 代理模式下，走代理的应用流量归属代理进程（如 mihomo），应用侧 TUN 重复流量不显示（与 AppNetworkCounter 一致）
- 代理进程与应用之间的虚拟转发流量（TUN 用户态）无法通过内核 ETW 观测，不显示
- 与 AppNetworkCounter 等 ETW 工具共用时：先启动的一方占用 NT Kernel Logger；后启动的 TM 进入附加模式（悬浮窗有黄色警告提示）
- ETW 占用者检测为尽力而为（Windows 无官方 API，普通权限下为已知工具名单识别）
- IP 归属地库（ip2region）首次使用时自动下载，失败会提示；可关闭或配置代理
