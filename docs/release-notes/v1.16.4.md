# ProcessNetMonitor v1.16.4 — 悬浮窗可一键关闭（issue #16），右键菜单与官方提示的避让全面加固

## 新增

- **「启用悬浮网速提示」开关**（[issue #16](https://github.com/deYangar/ProcessNetMonitor/issues/16)）：有用户反馈悬浮窗信息量大、窗口偏大，容易挡住 TrafficMonitor 官方鼠标提示，而官方提示里本就能看到实时网速——希望可以关掉悬浮的窗口，只保留点开后的详情页。插件设置新增开关（默认开启）：关闭后悬停 TM 窗口不再弹出悬浮窗、任务栏点击不再钉住弹出，流量信息只剩 TM 官方鼠标提示中插件提供的那段（与已有开关「在 TrafficMonitor 鼠标悬停提示中显示进程网速信息」各自独立控制，两者都关则悬停无任何提示）；设置保存后立即生效（正显示/钉住的悬浮窗当场收起）并持久化，旧配置文件无此字段视为开启

## 修复

- **右键打开菜单时悬浮窗躲让不及时、贴边场景甚至重新弹出**：右键后悬浮窗仍与菜单同屏最长约 400ms；菜单在屏幕边缘被系统翻转/平移后，光标常落回 TM 窗口上，悬停判定被骗过，悬浮窗会重新弹出压在菜单上；任务栏钉住的悬浮窗更是完全不躲。根因是躲让判定全靠「光标此刻在哪个窗口上」，而这在菜单模态循环里并不可靠。现在改用线程级菜单模式信号（`GetGUIThreadInfo`）：菜单一开悬浮窗立即隐藏（最迟一个 100ms 刷新周期）、菜单关闭前不再显示，钉住状态同样让位，且不再受菜单贴边翻转影响

- **悬浮窗可见时右键要按两次才能打开 TM 菜单**：此前悬浮窗可见时第一次右键只用于关掉悬浮窗（事件被插件消费，菜单不弹），第二次右键才出菜单。现在同一次右键三件事一起完成——悬浮窗让位、官方鼠标提示消失、TM 菜单直接弹出，与系统原生「右键 = 出菜单、提示让位」的习惯一致；右键未命中插件显示项的场景由上面的菜单模式检查兜底（最迟 100ms）

- **TM 主窗口右键后官方鼠标提示叠在菜单上最长约 1 秒**：上游 TrafficMonitor 只在任务栏窗口右键时同步隐藏官方提示，主窗口依赖 1 秒定时器兜底，期间提示一直压在菜单上。插件现在在右键瞬间替它发送隐藏消息（与任务栏窗口同款行为），主窗口/任务栏两处即时生效

- **悬浮窗被官方鼠标提示「推着跑」，移向「查看详细」按钮时点空**：官方提示跟随鼠标移动且每秒重建（文字宽度变化），矩形持续微动；旧逻辑只要矩形一变就整体重新定位——悬停 TM 窗口边缘时悬浮窗被一路推到屏幕边，移向按钮的过程中按钮位置持续变化，点下去时已不在原地。现在：官方提示真的压到悬浮窗上才避让（矩形微动一律忽略）；光标朝悬浮窗移动时（离开 TM 窗口、进入悬浮窗约 32px 范围）冻结一切移动，按钮钉死不跑；被挤开后须官方提示连续 500ms 不再重叠且光标不在附近才回到原位；数据刷新导致高度变化时保持左上角不动只改尺寸

- **悬停 TM 窗口时官方提示压住悬浮窗却不避让**（上一条的边界情形）：悬浮窗紧贴 TM 窗口弹出，而悬停的前提就是光标在 TM 窗口上——光标天然落在悬浮窗 32px 冻结圈内，「冻结」把初次避让也一起冻死，官方提示压顶无人躲。现在光标仍在 TM 窗口（含任务栏嵌入子窗口）上时不视为「接近」，该避让避让；只有光标离开 TM 窗口朝悬浮窗移动后才进入冻结保护

## 安装前提

1. Windows 10/11（推荐 64 位）
2. TrafficMonitor 主程序（插件版）
3. 插件以管理员权限运行时可启用 ETW 内核采集（更准）；普通权限自动回退传统采集并提示

## 已知说明

- TUN 代理模式下，走代理的应用流量归属代理进程（如 mihomo），应用侧 TUN 重复流量不显示（与 AppNetworkCounter 一致）
- 代理进程与应用之间的虚拟转发流量（TUN 用户态）无法通过内核 ETW 观测，不显示
- 与 AppNetworkCounter 等 ETW 工具共用时：先启动的一方占用 NT Kernel Logger；后启动的 TM 进入附加模式（悬浮窗有黄色警告提示）
- ETW 占用者检测为尽力而为（Windows 无官方 API，普通权限下为已知工具名单识别）
- IP 归属地库（ip2region）首次使用时自动下载，失败会提示；可关闭或配置代理
