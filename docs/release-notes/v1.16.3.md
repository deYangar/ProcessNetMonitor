# ProcessNetMonitor v1.16.3 — 修复中文进程名乱码，根治历史流量首次打开卡顿与汇总数据滞后

## 修复

- **中文进程名在 ETW 模式下显示为乱码**（issue #15，如「淘宝桌面版.exe」在内核字段里只剩 `D8 9D 4C 62…` 一类垃圾字节，界面显示成乱码、图标也取错）：根因是内核进程启动事件里的 `ImageFileName` 并非 ANSI 代码页编码，而是把真实 Unicode 名称**逐字符截断低字节**填入——中文名落到这里已是不可恢复的内容，旧逻辑却照样信任。现在只有纯 ASCII 名称才使用该字段，其余一律改从事件的 UTF-16 命令行路径中提取真实文件名；字段无正常结尾的畸形事件也不再污染后续解析。中文名进程从此正确显示名称与图标

- **历史流量页「总下载 / 总上传」总是慢一拍，显示的是上一个维度的数据**：典型现象——首次打开历史流量默认停在「今日」，总数长时间为 `0 0`；点「昨日」后出现的却是今日数字，再点回「今日」才变成昨日数字，有时要等很久才自己跳对。根因是数据本身在切换后 10ms 内已正确重算，但局部重绘的失效矩形只覆盖了表格区域，**汇总条恰好压在矩形边界之外**，只能等窗口被遮挡/还原等偶发的全窗重绘才会更新。现已把汇总条纳入失效范围，切换维度后总数与表格同一帧更新；实时流量页的同类问题一并修复

- **每次启动 TrafficMonitor 后首次打开历史流量界面会卡顿 1~2 秒，关掉再开却始终秒开**：根因是首次构建历史行时，所有进程的数字签名都还是冷缓存，后台验证线程**每验完一个 exe 就通知界面全量重建并重绘一次**（60 余个 exe、单个验证约 16~31ms，通知恰好连续打满 UI 线程）。改为整批验证完成后只通知一次，首次打开与后续打开一样流畅；「程序类别」列从未知变为最终分类只会多等一个批次周期

- **详情窗口关闭期间仍在后台每 500ms 重建一次表格**（纯空转，数据不断变化就一直重建）：窗口隐藏时跳过界面重建，仅保留历史流量采样与 30 秒自动存盘，降低无谓 CPU 占用

- 小幅加固：高频刷新定时器创建失败时正确清零句柄，避免失败后误删无效句柄；界面语言设置写盘时显式按 UTF-8 转换（当前取值均为纯 ASCII，属预防性加固）

## 安装前提

1. Windows 10/11（推荐 64 位）
2. TrafficMonitor 主程序（插件版）
3. 插件以管理员权限运行时可启用 ETW 内核采集（更准）；普通权限自动回退传统采集并提示

## 已知说明

- TUN 代理模式下，走代理的应用流量归属代理进程（如 mihomo），应用侧 TUN 重复流量不显示（与 AppNetworkCounter 一致）
- 代理进程与应用之间的虚拟转发流量（TUN 用户态）无法通过内核 ETW 观测，不显示
- 与 AppNetworkCounter 等 ETW 工具共用时：先启动的一方占用 NT Kernel Logger；后启动的 TM 进入附加模式（悬浮窗有黄色警告提示）
- ETW 占用者检测为尽力而为（Windows 无官方 API，普通权限下为已知工具名单识别）
- IP 归属地库（ip2region）首次使用时自动下载，失败会提示；可关闭或配置代理
